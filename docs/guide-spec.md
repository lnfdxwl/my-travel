# 攻略规范

> 加载时机：新建攻略、修改每日行程或攻略结构时读取。

## 文件命名

- 文件夹：`trips/{目的地拼音/英文}-{年份}/`，如 `uzbekistan-2026`
- 攻略文件：`{目的地}-trip-guide-v{N}.html`
- 模板位置：`templates/trip-guide-template.html`

## 版本规则

攻略文件名加版本后缀：`{目的地}-trip-guide-v1.html`、`v2.html`…

**版本升级原则**：
- 不确定时主动问主人，不自作主张
- 通常触发升版本的情况：行程结构变化（城市增减、天数调整、主要交通方式变更、整体重排）
- 通常不升版本的情况：时间微调、价格更新、补充说明、错别字修正

同一目的地多个版本并存于同一文件夹，方便回溯对比。

## 攻略 HTML 内容结构

参考 `templates/trip-guide-template.html`，标准章节顺序：

1. Hero 头图（目的地、日期、人数、出发地）
2. 行程概览（交通时刻卡片 + 城市游览顺序）
3. 每日行程（按 Day 分块，含时间轴、现场导览与逐段交通）
4. 酒店推荐
5. 餐饮推荐
6. 交通订票指南（订票步骤 + 备选班次对比表）
7. 💰 人均预算汇总（不含国际往返机票，见下方"预算汇总规范"）
8. 实用信息（货币、通讯、天气、打车）
9. 出行前准备清单
10. 决策记录（可选，记录行程取舍过程）

## 发布流程

攻略写完、commit 之前，默认起一个子 agent 做发布前审核（不用每次都问用户要不要审），重点查：

1. 每个 Day 的日期/星期标签是否与实际日历匹配
2. 时间块衔接是否存在时间倒流、重叠或过紧（尤其航班落地/起飞、跨城转场衔接处）
3. 有开放时间限制的景点，安排的参观时间段是否违反其自身写的开放/关闭时间（含公休日、午休时段）
4. "行程概览"、"预算汇总"、"实用信息"三处反复出现的数字（航班号、价格、酒店晚数、天数）是否互相一致
5. 只打开“每日行程”，从每天的住宿或抵达站出发，按时间顺序走到当晚住宿或离境站。逐段点开导航，核对两端、交通方式，以及落客点到入口的最后一段；把用餐、取行李和回程也算在内。逐一修复需要读者自己查“怎么过去”的断点。
6. 逐个读主景点：能否在现场找到入口或集合点，按顺序看到具体看点，并知道何时离开？核对门票是否含在联票或包车费内。碰上闭馆、封路或下雨，替代路线要能接回原行程。

发现问题就修，没问题就跳过；如果审出问题，修完后不需要重新整轮审核，确认改动本身没有引入新的时间/地点错误即可。

审核通过后 push 到 GitHub，自动发布：

```bash
git add . && git commit -m "更新攻略" && git push
```

1-2 分钟后访问：`https://lnfdxwl.github.io/my-travel/trips/{目的地}-{年份}/{文件}.html`

## 谷歌地图链接规范

攻略中所有**景点、酒店、火车站、机场**都必须附带谷歌地图链接，方便直接导航。

地点旁保留当地名称与坐标地图，核实标记落在对应建筑、入口或航站楼。线路用带起点和终点的导航，见下文“景点间交通规范”。同一机场的国际出发、国内到达与航站楼换乘应分别核实。

```html
<a href="https://maps.google.com/?q={lat},{lng}" target="_blank" rel="noopener" style="color:#2563a8;text-decoration:none;font-size:13px;">📍地图</a>
```

**加链接的位置**：
- 每日行程的 `.activity` 里，紧跟地点名称后
- 酒店详情卡片的 `.name` 里
- 实用信息的交通章节里

## 景点配图规范

每个主要景点在描述文字后插入一张真实照片，禁止用灰色占位框/emoji 凑数。

**获取流程**（使用 `google-maps` MCP）：
1. `maps_search_places` — 用景点名称搜索，获取 `place_id`
2. `maps_place_details`（`maxPhotos: 1`）— 获取真实照片 URL

**插入格式**：
```html
<img class="attraction-img" src="{photo_url}" alt="{景点名}">
<div class="attraction-img-caption">📷 {一句话说明}（图源 Google 地图）</div>
```

`.attraction-img` 用 `<img>` 标签展示真实照片（`object-fit: cover` 统一裁切），不要和旧的灰色占位框 `.attraction-img-placeholder` 混用；只有确实查不到照片的极少数情况（比如渡轮航程本身而非某个具体景点）才用占位框保底，不能留空。

## 景点历史背景规范

每个主要景点在 🧭 导览实操提示之外，补充 2-4 句历史文化背景，讲清楚"是什么、为什么叫这个名字、历史/文化意义"，不要只写实操建议。两者分工不同、都要有：

```html
<div class="bg">🏺 <strong>背景</strong>：{历史文化叙述，2-4句}</div>
<br><small style="color:#7c3aed;font-size:12px;">🧭 <strong>导览</strong>：{怎么玩的实操建议}</small>
```

导览要让人到了就能用。博物馆写从哪个入口或展区开始，挑一两件能认出来的展品，说明看哪处细节。街区给出步行方向与结束地标。自然景区拆出下车点、最后一段步行、观景位置和折返点。写清建议停留时间，以及影响游览的票价、预约和最后入场时间。若部分区域因宗教活动、潮汐或天气关闭，告诉读者还能在哪里看。

历史年代、具体展品、票价与开放条件优先查馆方、园方或当地主管部门，在对应日程保留出处。尚未公告的远期安排，写明何时、到哪里复核。

## 景点开放时间规范

每个景点活动后标注适用的开放时间。先查地图，再核对馆方或园方公告；两者有出入时采用运营方当期公告，保留出处。开放街区可写自由通行、店铺各自营业；查不到统一时段时说明情况。

**格式**（绿色小字，放在景点描述末尾）：
```html
<br><small style="color:#27ae60;font-size:12px;">🕐 开放时间：9:00–18:00（每日）</small>
```

特殊情况写法：
```html
<!-- 周一休息 -->
<br><small style="color:#27ae60;font-size:12px;">🕐 开放时间：7:00–19:00（周一休息）</small>
<!-- 工作日/周末不同 -->
<br><small style="color:#27ae60;font-size:12px;">🕐 开放时间：7:00–22:00（周一至五），9:00–22:00（周六日）</small>
<!-- 开放式广场/全天 -->
<br><small style="color:#27ae60;font-size:12px;">🕐 开放时间：8:00–24:00（每日至午夜，开放式广场）</small>
```

**查询流程**（使用 `google-maps` MCP，见 `docs/tools.md`）：
1. `maps_search_places` — 用景点名称搜索，获取 `place_id`
2. `maps_place_details` — 用 `place_id` 获取 `opening_hours.weekday_text`
3. 将每天的时间写入攻略；如各天一致写"每日"，如有例外逐一标注

## 打车指南规范

每份攻略的"实用信息"章节必须包含**打车完全指南**，内容包括：

1. 当地主流打车 App（如 Yandex Go、Grab、Bolt、Uber 等）
2. iOS/安卓安装方式（出发前在国内安装）
3. 注册方式（支持中国 +86 手机号）
4. 本行程所有关键路线的费用参考表
5. 注意事项（网络先行、不拦路边车、核对车牌等）

模板已包含完整结构，新建攻略时替换 App 名称和费用即可。

## 餐厅预订规范

攻略中每家**推荐餐厅**都需标注预订建议，尤其旺季出行：

- 用携程问道（`ctrip-wendao` skill）查询该餐厅旺季是否需要预订
- 需要预订的餐厅，在 `.desc` 里加 `⚠️ 建议/必须提前 X 天电话预订`，并附电话号码
- 每日行程中涉及该餐厅的 `.activity` 也同步加预订提醒

## 景点间交通规范

把换地点的交通写在当天两个活动之间，或写在下一站的开头。覆盖酒店出门、景点之间、去吃饭、回酒店取行李和去车站机场。同一广场内换馆可以只写方位和步行预留；跨区打车要给司机能识别的上下车点。

- 逐段写清 **起点 → 终点、交通方式、路程和耗时**。步行写实际入口或折返处；地铁、公交、轮渡写上下车站、方向和必要换乘；打车写上客区、费用按人或按车。遇到步行街、停车换吉普或码头换船，把换乘单列出来。
- 优先查实交通运营方、携程或地图的对应出行模式。地图服务不可用时，可用 OpenStreetMap 路网等可回查的数据，并给出处。注明路网里程、通常耗时或行程预留各自的含义。仅有直线距离时不写成步行里程；只有合理时间余量时标“预留”，附当日核实方法。
- 附能直接点开的带起点和终点的导航。步行与行车分别设置 `travelmode=walking` 或 `driving`，标清地点名称。景区管制路段按园方接驳和向导集合点走，地图上的直连线不代表能自行穿越。
- 在日程里实际扣除移动、排队及寄取行李时间；为固定班次写清最迟出发时刻。休闲日给一个方便折返的近处选择，保留原定自由时间。

```html
<div class="time-block">
  <div class="time">{离开上一站的时刻}–{到达时刻}</div>
  <div class="activity">从{出口}步行到{入口}，沿{容易认的街道或地标}。
    约{已核里程}，预留{分钟}。
    <a href="https://www.google.com/maps/dir/?api=1&amp;origin={起点}&amp;destination={终点}&amp;travelmode=walking">步行导航</a>
  </div>
</div>
```

## 预算汇总规范

在"实用信息"之前加一个"💰 人均预算汇总"章节，按类别列出人均参考价（国内段城际交通、酒店、门票、餐饮、市内交通、签证保险等），最后合计一行。

**必须明确排除国际往返机票**，并在合计行单独注明"加上国际机票¥X/人，全程总花费约¥Y/人"——国际机票通常由用户自行订好或价格波动大，不和境内花费混在一起算。

数字按行程里已经出现过的价格区间取中位数估算即可，不需要额外精确到个位；如果行程有可选分支（比如某天有 A/B 两个方案），在表格上方用一句话注明未计入的分支花销，不用把每个分支都拆成单独一行。

## HTML 设计风格

- 配色：主色 `#2563a8`（蓝）、辅色 `#d4a574`（金）、警示 `#c0392b`（红）
- 背景：`#f5f1e8`（米色）
- 组件：transport-item 卡片、day 块、time-block 时间轴、tip/warn/info 标注框、place-card 地点卡、checklist 清单
- 完整 CSS 见模板文件，不要自行修改风格，保持统一
